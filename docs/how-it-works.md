# 工作原理

这份文档说明镜像快车道在后台到底做了什么：改写规则怎么生成、镜像怎么挑、测速花多少流量、出错时怎么自救。只想装上就用的话，看 [README](../README.md) 就够了。

## 一、改写是怎么发生的

扩展用 `declarativeNetRequest`（DNR）在**浏览器网络层**重定向请求，不经过任何代理进程，也不碰页面里的内容：

```
https://github.com/<owner>/<repo>/releases/download/<tag>/<file>
        ↓ 命中 DNR 规则
https://<镜像域名>/https://github.com/<owner>/<repo>/releases/download/<tag>/<file>
```

镜像按「前缀拼接」的方式工作，所以原 URL 会完整出现在镜像地址里 —— 这也是为什么换了镜像仍然能下到同一个文件。

可选的两类：

- **源码包**：`codeload.github.com/<owner>/<repo>/tar.gz/...`
- **raw 单文件**：`raw.githubusercontent.com/<owner>/<repo>/<ref>/<path>`（默认关闭）

## 二、规则怎么生成

DNR 里**一个请求只会命中一条规则**，规则之间不存在「这个失败了再试下一个」的链式回退。所以扩展不给每个镜像都建一条永远轮不到的规则，只给真正会被用到的目标建：

| 规则 | 目标 | 开启条件 |
|---|---|---|
| 直链 `releases/download/…` | 得分最高的健康镜像 | 总是 |
| 源码包 `codeload.github.com/…` | 分流开启时换**第二个**健康镜像；关掉则同直链 | 设置里勾选「源码包」 |
| raw 单文件 `raw.githubusercontent.com/…` | 按 **raw 自身**的延迟排序取前 5 个健康镜像，按 owner 首字符分 5 组各走一个 | **默认关**，勾选时浏览器会弹一次权限确认 |

**为什么 raw 要单独一套**：大文件的吞吐排名和小文件的延迟排名不是一回事，混在一起会让某一类变慢。分成 5 片是为了避免所有 raw 请求挤在同一个镜像上被限流 —— 代价是某一片挂了，约 1/5 的 raw 地址会失败。

**raw 规则只作用于 `main_frame`**（直接打开链接 / 下载），不动 `xmlhttprequest` 与 `image`：镜像返回的 CORS 头与 GitHub 不同，改页面里的 fetch 会把原本能用的请求弄坏；图片则会让一个页面产生几十个小请求打镜像，既容易触发限流又可能更慢。

**为什么 raw 需要一次授权**：Chromium 只对「扩展拥有 host 权限的请求 URL」应用 redirect，而 `raw.githubusercontent.com` 属于可选权限。没拿到授权时扩展**不生成** raw 规则，避免注册一堆永不生效的规则；拒绝授权不影响 release / 源码包。

同一次点击里还会一并申请**当前 raw 分片用到的镜像域名**与可选的 `webRequest`：实测只给 raw host 权限时，被改写到镜像的请求只有「发起」事件、收不到「结果」事件，失败率就算不出来。分片换过之后可以用设置页的「补授权 raw 分片」补一次。

**分流不等于故障转移。** 「直链与源码包分走不同镜像」默认开启：两类流量来自不同源站、体量差一个量级，分开跑避免互相挤占，也避开单个镜像的限流（只有一个可用镜像时自动退化）。但某个镜像在两次测速之间挂掉，已生成的规则仍指向它，需要靠下一节的自愈路径恢复。

## 三、镜像清单

内置清单在 `data/builtin-mirrors.json`，按实测速度排序，打包进扩展。远程清单**默认关闭**，开启后按下面的顺序回退：

```
内置清单 → 经镜像拉远程 JSON → 直连拉远程 JSON → 保留上次缓存
```

远程 JSON 只当数据解析，字段白名单校验（只接受 https），**不会执行任何远程代码**。

### 清单会自动更新

`data/builtin-mirrors.json` 由 GitHub Actions 每天按 `git.mxg.pub` 的成功列表更新（`.github/workflows/update-mirrors.yml` + `tools/refresh-mirrors.mjs`）。规则是 **「手工精选 ∪ 源当前 success」**：

- **没有 `auto` 字段**的条目是手工精选（实测较快的那些），脚本**永不删**；
- 其余部分**整段按源当前的 success 覆盖**（顺序与地址都跟源走），条目用 `auto: true` 标出 —— 这正是扩展侧「连续 24 小时缺失才移除」的输入；
- 源解析后为空或全部失败时，脚本**直接报错退出**，不覆盖文件。

为什么不整份替换：源的可用集与本项目自测的内置集几乎不重叠，整份替换会冲掉实测更快的镜像。设计过程见 [mirror-list-pipeline.md](./mirror-list-pipeline.md)。

### 列表会自己增删吗

开启远程清单后，设置页有「允许删除镜像」开关（默认开）：

- **远程清单加进来的镜像**：连续 24 小时不在成功列表里才移除（相邻两次观测间隔超过 48 小时视为离线，重新计时，不误删）；
- **内置镜像**：永不因缺失删除 —— 源没测它不等于它挂了，只会被扩展自身探测降权、不再被选中；启动 / 升级时会**补齐**内置清单里缺失的条目，手动删掉的内置镜像会被记下来，不会复活；
- **手动添加的镜像**：永不自动删除；
- **抓取失败 / 格式不认识 / 清单为空**：这一轮不做缺失判定，一个都不删。

### 授权只影响测速

跳转本身不需要镜像域名的可选授权，「不授权也能正常用」（Firefox 与 Chromium 均实测：零授权时规则照常生成，release 直链命中并被改写到内置清单首条）。但**不授权意味着永远用它**：

- 没有测速数据时，`chooseMirrors` 按清单里的 `score`（内置顺序）取第一条，不会按你的网络调整；
- 这条镜像如果此刻不可用，下载就会失败。真实下载中断会把该镜像记一次故障，但**连续 3 次**才判 `healthy:false` 并换下一个，且同一镜像 10 分钟内只计一次 —— 也就是最坏情况要连失败三次才自愈；
- 授权并测速后，规则直接指向你这边实测最快的镜像，跳过这段试错。

所以「授权」不是功能开关，是「一次挑对」的开关。设置页的「需授权」标签只表示没测过速，鼠标悬停会写明这一点。

但浏览器层面的「站点访问 / 全部网址」总开关若被关掉，扩展对任何站点的请求都会被隔离，改写也不会发生 —— 那是浏览器设置，不是扩展的权限。

设置页有两个批量授权按钮：「一键授权内置镜像」只覆盖内置的那几个；「授权远程镜像」只授权**此刻已在列表里**的远程镜像，之后清单新增的不会跟着被授权（浏览器只允许在用户点击的当下申请权限）。授权状态一律以浏览器的 `permissions.contains` 为准回填。

## 四、测速、自愈与可观测性

- **真实下载失败**：`downloads.onChanged` 里的 `interrupted`（排除用户取消、关机、浏览器崩溃）会给对应镜像记一次故障并重建规则，自动换到下一个健康镜像；同一镜像 10 分钟内只记一次，避免失败风暴。
- **raw 请求失败率**：开启 raw 后统计最近 30 分钟**真实 raw 请求**的成败（只看 URL 与状态码，不读内容、不阻断）。404/410 是「文件真的不存在」，不计成败；429/5xx 才算镜像故障。失败占比达到阈值（默认 30%，至少 5 个样本）会**立刻重测 raw 分片并重排 top 5**，随后冷却（默认 5 分钟）。样本只存本机。
  - 观测不到结果的请求（多为分片域名还没授权）记为「无法观测」，**不计入分母**，避免把「看不见」误判成「失败」；设置页能看到这个数字并一键补授权。
- **探测预算**：单次探测 64 KB；按时 / 按需探测跳过 `probeCacheHours`（默认 2 小时）内已测过且健康的镜像，按「最久没测」轮转、每轮最多 6 个，并发 6。**坏镜像每轮只占 1 个名额**（最久没测的那个），既不让它们拖慢整轮，又保留恢复健康的机会；探测失败时**保留上次测得的速度**，单次抖动不会把好镜像清零。手动「立即测速全部」仍测全部。
- **判定修正**：200 的 HTML 错误页、只读到几百字节都不算健康；超时但已读够 8 KB 算「部分成功」（速度偏低自然降权）。
- **规则失败可见**：`updateDynamicRules` 抛错时徽章变 `!`、设置页显示红字，不会停在上一次的「生效中」。
- **少唤醒**：没开「生效时段」时不创建 5 分钟 tick；每次唤醒用规则指纹比对，规则没变就不做 DNR 全删全加（并用实际规则条数兜底，防止规则被外部清空后永不重建）。
- **并发写入**：镜像表的所有读-改-写排队；探测跑几十秒后按**最新**列表合并探测字段，这期间的停用 / 删除不会被静默回滚。
- **看得见的数据**：清单里的 `note`（如「IDM 建议 4 连接」）与 `seedKbps` 会显示在镜像列表；「诊断」区可导出脱敏 JSON 快照（Token 打码），正式包也能自查。
- **一键自检**：「诊断」区能跑一次自检，按 OK / WARN / FAIL 列出规则、权限、可用镜像、storage、远程清单与最近探测，结果可一键复制。
- **权限被拒可自救**：申请失败、或「已开启但权限被撤销」时，设置页直接给出下一步路径（Firefox：`about:addons` → 权限 → 访问网站；Chromium：扩展详情页 → 站点访问权限），并可复制。

## 五、跨浏览器的差异

`downloads.download()` 对 URL 协议的要求在两个内核上相反，实现里已分别处理：

| | `data:` URL | `blob:` URL |
|---|---|---|
| Chromium（Service Worker） | 可用 | 没有 `URL.createObjectURL` |
| Firefox（Event page） | `Access denied for URL data:` | 可用 |

另外，Firefox 在 `permissions.request` 之前**不能有任何 await** —— 一旦让出，用户手势就失效，表现为权限弹窗不出现、开关自动弹回。所有申请都写成点击处理函数里的第一个 await。
