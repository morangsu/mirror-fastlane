## 详细描述（10000 字符）

```
镜像快车道解决一个很具体的问题：GitHub 的 release 下载在国内经常几十 KB/s，甚至直接断开。它做的事只有一件——把你点击的下载链接换成一个可用的镜像地址，让你在页面上就能看清"这次是谁在给你传文件"。

■ 它怎么工作

1. 你在 GitHub 的 release 页面点下载，扩展按测速得分把请求改写到最快的镜像；
2. 链接旁边会出现一个「镜像」徽章，悬停能看到具体是哪个域名在服务；
3. 点击下载时右下角弹出提示，告诉你走了哪个镜像；
4. 镜像失效时，扩展在下一轮测速里把它降级，换上可用的那个。

■ 默认就很克制

- 探测模式默认「仅按需」：只有你打开 GitHub 页面时才测速，不会在后台定时消耗镜像流量；
- 支持生效时段（例如 20:00–02:00），时段外不测速、不改写，一切回退到主站；
- 远程镜像清单默认关闭，需要你自己开启并填写地址；
- 所有配置只存在本机浏览器里，没有账号、没有云端。

■ 你也可以自己加镜像

设置页里可以增删镜像、单独授权、单独测速。是否授权只影响"能不能测速"，不影响改写——改写本身不需要访问镜像站点的权限。源码和镜像清单都在 GitHub 上，改起来没有门槛。

■ 可选的下载校验

如果你在意"下到的文件是不是原版"，可以打开哈希校验：下载时扩展会把该资产的官方 SHA-256（来自 api.github.com）写成一个任务文件，配合同仓库的本地脚本在下载完成后自动比对并弹系统通知。脚本还会拿资产 id 回源 GitHub 再核对一次，防止任务文件被改写后自说自话。

这一步完全可选，脚本不随扩展打包，需要你自行下载并审查。

■ 它不做什么

- 不代理网页浏览，不是 VPN，不改变你的出口 IP；
- 不缓存、不上传、不收集任何数据，没有遥测；
- 不改写浏览器之外的请求（例如你直接粘贴给下载器的原链）；
- 不读你的下载内容（只有开启哈希校验时，扩展写一个几十字节的任务文件）。

■ 适合谁

经常从 GitHub 拉 release、源码包的人；对"文件是否被替换"有要求的人；不想为了下个软件去折腾全局代理的人。

MIT 协议开源，源码与问题反馈都在 GitHub。
```
